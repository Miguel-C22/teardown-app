Context

Only F0 (project setup) of the guide's 12 features is built in desktop/teardown-poc. It has a home page, a health route and empty /scan and /bench screens, so there is nothing a tech can test yet. The guide's first hands-on milestone is P1: a barcode-only session (F0–F3 + F10): exit check is "one real server torn down with every drive and PSU captured by serial."

Before F1 (needs the user)

- Trusted HTTPS: the user runs winget install FiloSottile.mkcert + mkcert -install, then generate .certs/cert.pem/key.pem for localhost + laptop IP. Without this, the Chrome check stays blocked and phones can't open the camera.
- Decide whether to move the project off the OneDrive-synced Desktop (e.g. C:\dev\teardown-poc) so node_modules doesn't sync.
- Run the skipped F0 Chrome check once the cert is trusted.

Features, in order (each: tests first → build → npm test + npm run e2e → Chrome check → stop for go)

1.  F1 Session + parent server: local SQLite file in data/ (server/src/store.ts), POST/GET /api/sessions, start screen on /scan (type or scan asset tag + model). Tests: session stored; adding a part before a parent exists is refused.
2.  F2 Camera + barcodes: ZXing WASM decoding in web/src/scan/, multiple codes per frame, overlay boxes, ?feed= test-feed mode (development builds only), fixture images + a short clip in fixtures/. Playwright gets fake-camera Chrome flags.
3.  F3 Units + dedup: pure dedup in shared/src/dedup.ts, POST /api/sessions/:id/units, cooldown, "already recorded", no-serial goes to REVIEW. Tests: 16 DIMM serials → quantity 16.
4.  F10 CSV export: shared/src/csvExport.ts + GET /api/sessions/:id/export.csv, button on a simple /bench list. Tests: one row per unit, all columns.

Verification for P1

- All Vitest + Playwright suites green at desktop and phone widths.
- Chrome check per feature: screenshots at desktop and 400px, console clean, GIF of the flow.
- User's hands-on phone check over HTTPS on a real server teardown (P1 exit check), then decide whether to continue to P2.
